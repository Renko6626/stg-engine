## 结论（帧预算 16667 µs @60Hz）

1. **模拟本体极其便宜**：满池 8192 哑弹 ≈ 110µs = **0.7% 帧预算**；变换弹逐帧 sincos
   回填约为哑弹 4-5× 单价，段池满载 2048 发也只 ~300µs；真实游戏规模（~200 弹全机制
   混合）≈ 20µs。**ECL 指令预算可以定得很宽裕**——以 ~10ns/指令估算，每帧 1 万条指令
   ≈ 100µs 量级，完全可负担（M1 grill 时以此定防死循环上限）。
2. **校验和是最大单项成本**（1.3-2.1ms/帧，为 step 本体的 10-20×）：FNV-1a 逐字节扫
   0.92MB 所致。金向量/CI 逐帧算无碍（离线）；**联机随包 K=20 采样的既定设计被实测
   证实必要**（摊薄后 ~70µs/帧）；将来若在意可议分块/增量哈希，现无必要。
3. **rollback 完全可行**（M3 定心丸）：快照 memcpy 170-460µs、16 帧环 14.7MB；
   最坏 16 帧重演 ≈ 16×300µs ≈ 5ms，一帧预算内吃得下。
4. p99 尾部（数百 µs 级）主要是 Windows 调度噪声与批量补弹帧，非模拟本身的病态路径。

### 结论增补(第三轮)

- 校验和/step 比值实测 13-265×（视场景；全混合最高见 265×〔1564.8/5.9〕，xform 2048 满载
  最低见 13×〔1564.7/116.9〕；第二轮口径 10-20×，A2 所记"远超"于此对账坐实——低弹量/全混合
  场景下校验和（近乎常数，由 World 总字节数主导）相对 step 本体的倍率显著抬升）；
- M2 帧预算决策依据以本轮为准（单机不逐帧算校验和；联机 K=20 采样摊薄至
  1564.8/20≈78µs/帧，与 F2 裁决记录的估算一致）。
