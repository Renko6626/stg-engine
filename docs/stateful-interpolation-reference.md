# TH18 mode7／8／17：状态、参数与注入方式

2026-10-23。原生调查限定TH18 v1.00a；我方显式值槽已在 ENGINE_VER 26 实现。
这些模式不属于我方 `Easing` 的30条曲线。

## 同一份存储，在不同mode下解释为不同参数

原作标量插值对象占0x30字节。下表采用语义名，不把社区结构体的 `goal/bezier_*` 字段名
当作所有mode下的实际含义。字段位置及消费已核对本机原生代码。

| 对象偏移 | 普通曲线 | mode7：累加 | mode8：Hermite | mode17：二阶累加 |
|---:|---|---|---|---|
| `+0x00` | 起点 | 当前累计值，可被改写 | 起点 `p0` | 当前累计值，可被改写 |
| `+0x04` | 终点 | 每次增量 `delta` | 终点 `p1` | 加速度 `a` |
| `+0x08` | 普通曲线不用 | 不用 | 起点切线 `m0` | 不用 |
| `+0x0c` | 普通曲线不用 | 不用 | 终点切线 `m1` | 当前速度 `v`，逐次改写 |
| `+0x10` | 本次结果 | 本次结果 | 本次结果 | 本次结果 |
| `+0x14..0x27` | 计时器 | 计时器 | 计时器 | 计时器 |
| `+0x28` | 时长 | 时长 | 时长 | 时长 |
| `+0x2c` | mode | 7 | 8 | 17 |

运动用的向量插值器保存对应向量字段，位置布局不同，计算语义相同。
这解释了原作为什么同一个参数在一种mode里像目标、在另一种里像变化率。

## 每次有效更新做什么

### mode7：每次累加一个增量

```text
value = value + delta
result = value
```

它没有“必须到达的终点”。例如初值10、增量2，有效更新结果为12、14、16……。
时限结束后保留累计值，不跳到存放delta的字段。

应用到角度上是固定角增量，应用到速率上则是固定速率增量；不能根据mode7就笼统称它为
“匀速移动”。实际物理意义取决于被驱动的量。

### mode17：先累加当前速度，再改速度

```text
value = value + velocity
velocity = velocity + acceleration
result = value
```

顺序不能颠倒。初值0、初速2、加速度1，有效更新结果为2、5、9，更新后的速度为3、4、5。
做了k次有效更新后，数学表达为 `value0 + k*v0 + k*(k−1)*a/2`。
原生逐次浮点相加有舍入，不能据公式声称逐位等价。

结束时同样保留累计值，不跳到加速度字段。位置使用它是匀加速；角度使用它是角加速；
速率使用它则是“加速度还在逐次变化”，三者不能混成一个物理接口。

### mode8：两个端点、两条切线的三次Hermite插值

令 `t=elapsed/duration`，原生消费公式为：

```text
result = (2t³−3t²+1)*p0 + (−2t³+3t²)*p1
       + (t³−2t²+t)*m0 + (t³−t²)*m1
```

`m0/m1` 是对归一化时间t的切线，不是两个中间点，也不是直接以px/frame表示的速度。
若希望物理起止速度为 `v0/v1`、持续T帧，数学上应传 `m0=T*v0`、`m1=T*v1`。
若想用Bezier控制点表示，则 `B1=p0+m0/3`、`B2=p1−m1/3`。
原生指令虽名为 `moveBezier`，本轮核到的存储与消费是上述Hermite形式。

## 参数如何由ECL注入

### 变量插值：91与92号指令

以下为便于说明的伪签名，不是我方ECL现有函数：

```text
ins91(slot, destination, frames, mode, start, goal)
ins92(slot, destination, frames, mode, start, goal, extra1, extra2)
```

- 上下文中有8个变量插值槽；这组状态属于ECL运行上下文，不是一个全局共享槽。
- 参数通过原生整数／浮点取参器求值，可来自字面量、变量和表达式栈。指令执行时把数值
  写进插值对象；后续每帧不会重新读取这些输入变量。
- 91写入start、goal，并把两个extra清0。92还从最后两个浮点参数写入extra1／extra2。
- mode7把goal解释为delta；mode8把extra1／extra2解释为m0／m1；mode17把goal解释为a、
  extra2解释为v0。仅用91启用mode17时初速为0。
- destination不是动画回调。原生记录建立该插值的指令位置和源栈基准，后续定位写入目标，
  每次推进后把结果写回对应变量。因此需要保留目标的身份及所属调用上下文。

指令进入时还会读取／推进该槽原有插值，再建立新参数；重新配置不能默认理解为另起一条
完全不相关的协程。通用变量插值的替换、返回与生命周期属于后续接口设计事项。

### 敌人运动：405 `moveVelTime` 的mode7

伪签名：`moveVelTime(frames, mode, angle_arg, speed_arg)`。

原生建立两份标量插值：角度一份、速率一份。起点从当前运动层的角度、速率取值；
普通mode把后两参作为目标，mode7则把它们作为每次角度增量、每次速率增量。
两个extra均清0。原生对mode7还单独处理缺省值和镜像角增量，不能直接套普通目标角的转换。

22份素材中找到4处明确的字面mode7：`st05bs::BossCard4_Et` 和
`st06::GirlA04/GirlA05/GirlA06`。后三者角增量约±1°/次、速率增量0；这是实际转弯运动的正例，
不是只存在于引擎里的备用分支。

### 敌人路径：425 `moveBezier` / 426相对版

伪签名：

```text
moveBezier(frames, m0_x, m0_y, target_x, target_y, m1_x, m1_y)
```

原生选择绝对／相对运动层，写入：当前层位置作为p0，target作为p1，第一对浮点数作为m0，
最后一对浮点数作为m1，然后显式设置mode8并重置计时器。setter直接拷贝切线向量，
没有隐含乘时长或把控制点减起点。

22份素材中425有1处：`st07bs::BossCard8_et`。本轮未找到92或字面mode17的直接使用样本；
不能据此宣称整个游戏含ANM／硬编码路径都不用17。

## 我方ECL：独立指令与显式读取（ENGINE_VER 26）

用户确认采用独立操作与槽位，读取值时显式调用函数，不自动回写局部或全局变量。
三类槽各自编号 `0..INTERP_SLOTS_PER_KIND-1`，目前每任务每类4槽，初始值全为0。
数值参数与返回值均为 `fx`，槽号和帧数均为 `int`。

| 操作 | 参数 | syscall |
|---|---|---:|
| `accum_start` | slot, initial, delta, frames | 750 |
| `accum_value` | slot → fx | 160 |
| `accel_start` | slot, initial, velocity, acceleration, frames | 751 |
| `accel_value` | slot → fx | 161 |
| `hermite_start` | slot, start, end, tangent_start, tangent_end, frames | 752 |
| `hermite_value` | slot → fx | 162 |

例如：

```ecl
sub main() {
    accel_start(0, 0fx, 2fx, 1fx, 3);
    wait(1);
    var value: fx = accel_value(0); // 2fx；后续两次更新依次5fx、9fx
    wait(2);
    value = accel_value(0); // 9fx，之后保持
}
```

- 启动只求值一次并覆盖同类同号槽；读取不推进，也不改变变量。三类槽互相独立。
- 启动帧立即可读初值；下一有效任务帧起每帧更新一次，先推进再执行脚本，wait期间继续。
  累加／加速恰好更新N次后保持结果；加速先加旧速度、再改速度。整数raw相加按VM规则回绕。
- Hermite切线针对归一化时间t；没有隐含乘帧数，到期精确保持end。中间计算采用定点Q16.16，
  允许超调；超出i32的结果按VM字宽回绕。
- 帧数合法范围0–65535。0帧时，累加／加速保持initial，Hermite立即取end。
  坏槽或坏时长不修改槽，增加contract_viol并置BAD_ARGS；坏读取额外返回0。
- 同步sub调用共享当前任务的槽；spawn任务独立清零，不继承父槽；任务退出后停止推进。
  场景冻结停止任务相位及槽推进。槽状态纳入checksum、存档和快照，复用任务槽完整重置。
- 新增状态每任务208 B，256任务共53,248 B；WorldBody尺寸不变，World尺寸1,271,376 B。
  ENGINE_VER 25→26，旧存档／回放版本不兼容，旧golden校验和因新增零状态也会改变。

## ZUN转换边界

转换器识别源游戏版本与mode语义，再发射上述具名操作：mode7用accum，mode17用accel，
mode8用Hermite。源91/92的goal与extra字段先解释成delta、a/v0或m0/m1，不能直接按字段名搬运。
后续在脚本实际需要更新目标变量的位置显式读取槽，并调用既有变量／运动写接口。
原作存在自动目标变量写回，我方不新增变量引用或自动绑定机制。

原生计时器先推进再判断是否到期；我方明确N次有效更新。源初始化／结束帧、目标变量的
读写顺序、相位关系仍需转换微程序或原作轨迹对拍，不能把frames机械复制后宣称逐帧等价。
425/426运动向量的每个分量可分别用Hermite槽，但实际降低方案及槽分配仍属转换器后续工作；
本次没有新增Hermite运动写API，也没有扩展导入器。
