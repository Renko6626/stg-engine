# 敌人脚本共享变量区设计

2026-10-26。用户已确认容量、类型、四个 self 接口及版本变更，并以“ok 开干”授权实施。

## 目标与路线

同一敌人的主任务、同步调用和 async 可持续双向读写一份数值状态；不同敌人互相隔离。沿用现有 TaskPool、owner 和固定相位顺序，不改变任务私有局部变量、shooter 或状态插值槽。

继续使用 globals 无需新增状态，但需要手工分配每敌命名空间；在 ECL 侧另建按敌索引的共享表则增加创建/回收同步接缝。用户已选择 EnemyPool 内保存普通数值字段，世界层不持有任务类型或回调。

## 已确认接口

- EnemyPool 追加 `script_int: [i32; 4]` 和 `script_fx: [Fx; 8]`，常量 `ENEMY_INT_SLOTS=4`、`ENEMY_FX_SLOTS=8` 通过现有注册表注入 ECL。数值存储增加12 KiB（256敌×48 B）。
- ECL 新增 `self_int(slot: int) -> int`、`set_self_int(slot: int, value: int)`、`self_fx(slot: int) -> fx`、`set_self_fx(slot: int, value: fx)`。仅访问当前任务 owner 敌人，不接受另一任务或敌人的句柄。
- 角度暂用整数槽保存 BAM：`set_self_int(0, a as int)`，读取 `self_int(0) as angle`。不新增隐式转换或裸位读取接口。原作 F 槽的弧度角与我方类型映射仍由转换器处理，本功能不宣称完整数值兼容。
- 世界层提供对应的内部 EnemyHandle 读写方法；复用现有句柄校验和P4处置。syscall按现有约定弹参并调用世界方法，读号170/171、写号450/451，旧号不变。

## 生命周期与可观察语义

- 敌人创建/槽复用清零。创建新的独立任务不清零其owner敌人的变量，任务结束也不清零。
- 同一敌人换阶段保留数值；需要重置时脚本显式写入。不新增自动阶段重置或清空指令。
- 读写立即生效，后执行的任务看到先执行任务的写入；保持既有任务槽升序，不新增消息队列、帧缓冲或同步机制。
- 非敌owner调用按现有敌人专用syscall策略Fault。坏槽写入no-op、读取0，加一次违约计数并置BAD_ARGS；世界方法拿到失效句柄时沿用STALE_HANDLE处置，不读写复用后的敌人。
- 新敌人的变量默认0，不隐式继承创建者；源ECL的继承可由导入器用现有显式实参在子入口初始化，自动继承作为独立扩展。

## 版本与验证

新增字段自动随池的Checksum/SaveBytes/copy_into处理，所有EnemyInit必须显式初始化两组数组，池复用完整覆写。更新布局账与哨兵；ENGINE_VER26→27，旧存档/回放不兼容，新空槽从帧0起也会改变golden。

以实际行为覆盖同敌主/async双向读写、不同敌隔离、复用清零、坏槽处置及save/copy恢复后续算；在最适合的一层复用已有夹具，不机械重复覆盖。集中运行受影响的core/compiler/harness测试、fmt/clippy、元数据生成和表校验；本机新版本golden记录新哈希，不能要求与26版一致。

## 本次不扩展

不加入任意任务locals读写、返回值、通知协议、跨敌变量接口、共享shooter、弹任务带参、自动插值写回、训练卡池迁移或原作导入器扩展。前一批模块整理仍未提交，本功能不自动提交/推送，也不修改训练仓。
