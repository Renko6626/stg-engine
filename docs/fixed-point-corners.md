# 定点数 corner doc —— `Fx` / `Angle` 的坑与规范速查

面向：在 `stg-core` 数学核之上写代码的人，以及将来写 ECL VM / 脚本的人。
权威规格见 `stg-world-design.md` D1、`design_doc.md` §2.1；本文是"**容易翻车处**"的集中速查。

---

## 0. 先记这个心智模型

- `Fx = Q16.16 (i32)`：逻辑值 = `raw / 65536`。
- **`65536` 是 `1.0`，不是最大值**。逻辑幅度上限 ≈ **±32768**（raw 到 ±2.1e9 = i32 极限）。
- 屏幕才 ±450px，`Fx` 余量约 **70×**。位置 / 速度 / 半径 / 缩放都是"屏幕空间标量"，稳在范围内。
- **单位边界原则（贯穿全文）**：`Fx` 是屏幕空间标量。一旦运算产出"**离开屏幕空间**"的量（面积 /
  平方距离 / 点积），它已不是坐标 → **换 i64，别塞回 `Fx`**。

## 1. 乘法：`Q16.16 × Q16.16 = Q32.32`

- raw 积天然是 **Q32.32**（小数位 16+16）。`Fx::mul` = 得 Q32.32（i64 中间量）后 **`>>16` 归一化
  回 Q16.16(i32)**——这一步**既丢低 16 位、又是溢出源**（结果须 ≤ ±32768）。
- ✅ **安全条件**：至少一个操作数 ≤ ~1.0（三角值 / easing-t / 归一化权重 / 小缩放）。
  例：`speed × 单位向量`、`位移 × ease_t`、`坐标 × 权重`。
- ❌ **两个大坐标相乘**（平方距离 / 点积 / 模平方）：坐标差一过 ~181px，其平方就出 `Fx` 范围 → 溢出。
- ✅ **正解**：保留 Q32.32 于 **i64、不归一化**——`math::geom::len_sq(dx, dy) -> i64`；
  碰撞比较 `dsq <= (r.raw() as i64).pow(2)`（`r²` 同为 Q32.32），**直接比、不开根**。
- 通用律：`Q(m).f × Q(m).f = Q(2m).(2f)`；`>>f` 才归一化回 `Q(m).f`；**保留双宽 = 累加器模式**。
- i64 余量：满屏平方距离 ~2⁵¹，i64 到 2⁶³，约 **4000×** 富余（只有喂进近 ±32768 的极值才会爆 i64，
  而位置到不了那量级）。

## 2. 加 / 减：朴素 `+` `-`，溢出交给 profile

- `Fx` 的 add/sub = 内层 i32 的 `+` / `-`；溢出行为由 `overflow-checks` 决定：
  **debug `panic`（抓 bug）/ release `wrapping`（确定、零成本）**。（`Cargo.toml` 两个 profile 已设。）
- ❌ **不用** `wrapping_add`（会吃掉 debug 的 panic，静默藏 bug）、`checked_add`（`Option` 在
  `pos += vel`×8192 的热循环里是人体工学灾难，且溢出=bug 不该"处理"）、`saturating_add`
  （静默钳出错值、非物理）。
- 依据不是确定性（四者都确定），而是**抓虫**：坐标 ≤±450 ≪ ±32768，溢出=设计错误，就该在 debug 炸。

## 3. 角度 `Angle`：语义回绕，必须 `wrapping`

- `Angle = BAM u16`，一圈 65536，天然 mod 回绕。
- **一律 `Angle::add / sub / add_delta`（内部 `wrapping_*`），绝不用 `+`**——否则 debug overflow-checks
  会在**正常回绕**（如 `60000 + 10000`）误 `panic`。
- 对比：`Fx` 溢出 = bug（要 panic）；`Angle` 回绕 = 正常（要静默 wrap）。**两种意图、两种机制**。
- `deg → BAM`：`deg × 65536 / 360`（编译期算）。

## 4. 除法 & `mul` 的守卫（两个溢出点两套抓法）

- `Fx::div` = `((a as i64) << 16) / b`，**向零截断**；**除零永远 panic**（debug + release）——调用方别传 0。
- `Fx::mul` 的溢出守卫是**手写 `debug_assert!`**：因为 `>>16 as i32` 的 **cast 永远静默截断**，
  profile 的 overflow-checks 管不着 cast。→ **add/sub 靠 profile 的 `+`，mul 靠 `debug_assert!`**。
- danmaku 热路径基本不用除法（碰撞比平方距离、不开根）。

## 5. ECL / 脚本层：定点被藏起来，作者基本不碰

- **VM 内部**：`addi/addf`、`muli/mulf` 各写一份（调 `Fx`/`geom` 核），封闭集合、写一次、测一次。
- **编译器负责"别配错"（§4.3）**：作者写 `speed = 3.5`、`aim + 15 deg`，编译期转 `3.5 → 229376`、
  `15 deg → 2730`，选对 `addi/addf`，类型不匹配直接编译报错。人永远不写 `229376` / `>>16`。
- **几何防火墙**：脚本调 `aim_player / set_speed / move_to / …`，**不自己算 vec/dist**——"运算规范"
  的负担落在引擎（Rust），不落在脚本作者。
- 脚本实际算的多是 int 计数、BAM 角度步进、小速度设定——**很少碰定点乘**。
- **M1 过渡**（Rust DSL 拼字节码）：加 `fx!(3.5)` / `deg!(45)` 编译期宏（compiler crate，断层线以上），
  避免裸 `229376`。

## 6. 大数 / 参数方程轨迹：决策树

原则：把"大数 / 怪参数"关在**注入世界之前**，世界层只收 in-range `Fx`。

```
形状创作期已知？ ── 是 ──► A. 烘成路径表（WorldTables 图样描述符，同 sin/easing 纪律，最稳）
        │否
可拆成 角度步进 + 幅度×单位 / 前向差分？ ── 是 ──► B. 增量式（逐帧只加法）
        │否
大数是单位问题？ ── 是 ──► C. 重标定：编译期折叠大常数，令 t∈[0,1]
        │否（真需要宽中间量）
        └──► D. i64(Q32.32) 暂存累加，注入时 `>>16` 窄化成 Fx（需 VM 宽 opcode，用时再加，Part IV 增量）
                └ 仍不够（罕见）──► E. 该弹用 Q32.32 位置字段（§10.2，金向量实测出病例才上）
```

- **B 的关键**：`x = A·sin(3t)` → 角度 BAM 累加（`θ += 3·step`，随便绕、无大乘）＋ 幅度 `A·sin`
  （`A≤450`、`sin≤1`，乘积安全）；多项式路径用**前向差分**（逐帧 `p+=Δp; Δp+=Δ²p; …` 只加法，
  大系数只出现在一次性差分初始化 / i64 / 编译期）。
- 贯穿：**大数只活在一次性设置**（烘表 / 派生时 i64 差分 / 编译期折叠）；**逐帧运行时永远是小整数
  加法 + 有界乘法**；无运行时浮点，确定性不破。

## 7. 速查："想做 X → 用 Y，别用 Z"

| 想做 | ✅ 用 | ❌ 别用 |
|---|---|---|
| 两个屏幕量相加 | `a + b`（profile 管溢出） | `wrapping_add`（吃掉 debug 抓虫） |
| 速度 × 方向（一个 ≤1） | `speed * cos` / `polar_to_vec` | 手算 vx/vy 各写一遍 |
| 平方距离 / 点积 / 模平方 | `geom::len_sq` → i64，比 `r²`(i64) | `Fx::mul`（两大坐标相乘必溢出） |
| 角度加减 / 步进 | `Angle::add / add_delta`（wrapping） | `+`（正常回绕会 panic） |
| 缓动插值 | `ease(curve, t)`、`(to−from)*ease_t` | —— |
| 脚本里写小数 / 角度 | `3.5` / `15 deg`（编译期转） | 手写 `229376` / `2730` |
| 参数方程大参数 | 烘表 / 增量 / i64 暂存窄化 | 运行时浮点、或"大×大"塞 `Fx` |
